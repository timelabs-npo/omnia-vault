# Network facts and correction brief for Antigravity

Reviewed 12 September 2026. Public upstream documentation and source only. This review did not run network tests, install software, or change the active project. Keep the user's updated Gate 4 result—scion-skip/PAC requests to YouTube and Ozon returned HTTP 200/301—as a reported successful result. Do not replace it with earlier assumptions about missing binaries or a failed setup.

## Quick view

1. **Describe SCION as path-aware inter-domain networking.** It provides route control, failure isolation, and explicit routing trust. It does not itself provide end-to-end payload encryption or user identity authentication. Replace any automatic “SCION encrypted” or universal “VPN eliminated” claim with the actual measured protection and traffic scope. A deployment may replace a particular VPN use case, but that is an application/deployment result. [SCION overview](https://docs.scion.org/en/latest/overview.html)

2. **Remove “Blended Multi-Path Warm Flow” and “Hot/Cold Valve” from product labels.** They are not verified stock feature names in the reviewed SCION/GNS3 documentation. Explain the behavior in normal language: which traffic is active, which path is held ready, what a switch changes, and whether it affects existing connections. Map each control to an existing configuration/API/code function. If no working implementation exists, remove the control from normal operation; do not add a new transport architecture just to justify a label. Upstream SIG terminology is traffic class, path class, performance policy, and path count. [SIG terminology](https://docs.scion.org/en/v0.15.1/manuals/gateway.html#nomenclature)

3. **Separate path availability from traffic using several paths.** A list of two available paths does not prove that two paths carry traffic. SIG documentation describes balancing different flows across paths; the default path count is one. SIG framing keeps the frames of one stream on the same path to preserve order. Do not promise automatic packet blending, bandwidth addition for one download, or interruption-free handover from this alone. Some listed performance policies are explicitly not implemented. [SIG policy](https://docs.scion.org/en/v0.15.1/manuals/gateway.html#path-count), [SIG framing](https://docs.scion.org/en/latest/sig.html#sig-framing-protocol)

4. **Name GNS3's actual role.** GNS3 manages projects, computes, emulators, and their virtual links. The compute starts QEMU/Docker/etc.; the controller manages them through its API. “GNS3 Hypervisor” should become “GNS3 server” or “GNS3 compute” unless the UI identifies an actual underlying hypervisor. A connected controller or a running node does not prove that SCION traffic passes through that node. Bind the display to the real project, compute, node, and link IDs. [GNS3 architecture](https://docs.gns3.com/docs/using-gns3/design/architecture), [GNS3 3.1 compute model](https://docs.gns3.com/docs-3.1-en/web-ui/manage-computes)

## Deeper checks for the correction task

5. **Keep host networking boundaries visible in the engineering evidence.** The reference SCION implementation normally runs over UDP/IP and standard OS sockets. It does not bypass the Windows/WSL kernel, routing, NAT, or firewall simply by being SCION or by crossing a C FFI. Record where each process and interface actually runs; avoid calling a simulated log line “native L2 injection.” This is a statement about the stack, not a request to repeat the user's network audit. [SCION underlay](https://docs.scion.org/en/latest/protocols/underlay.html)

6. **Identify the real destination and egress method.** Native SCION requires a SCION endpoint. Stock SIG carries IP between gateway peers, using ordinary IP routing before encapsulation and after decapsulation. A normal Internet domain is not converted into a SCION endpoint by putting it in a label or PAC rule. For a claimed SCION web request, identify the SCION endpoint or web/IP gateway and its onward connection. [IP-in-SCION](https://docs.scion.org/en/latest/sig.html), [SCION application repository](https://github.com/netsec-ethz/scion-apps)

7. **Do not claim that current scion-skip lacks HTTPS support.** The reviewed upstream `skip/main.go` has a CONNECT handler. It selects its SCION dialer when the target resolves as SCION; otherwise it opens ordinary TCP/IP. That fallback is legitimate behavior, but the UI must distinguish it. The upstream file also labels its path statistics as presentation code, assumes one path per domain, counts received bytes, and leaves HTTP path reporting unfinished. Do not promote those fields into complete per-flow telemetry without checking the installed implementation. [Source pinned to 6c990ccb5b39fe0f7a23a3d8dcb4528439c3f5c5](https://github.com/netsec-ethz/scion-apps/blob/6c990ccb5b39fe0f7a23a3d8dcb4528439c3f5c5/skip/main.go)

8. **Make PAC scope and HTTPS behavior precise.** PAC chooses a proxy for participating clients; it is not a system-wide packet router. In Chrome, HTTPS URL paths and queries are removed before PAC evaluation. Host-based choices can work; HTTPS page-path rules cannot be assumed. HTTPS through an HTTP proxy normally uses CONNECT and retains the browser's TLS session to the destination. Record the browser and effective proxy choice. Do not infer whether traffic used SCION from the website name alone. [Chrome proxy behavior](https://chromium.googlesource.com/chromium/src/+/HEAD/net/docs/proxy.md)

9. **Keep HTTP status and route evidence as separate facts.** Preserve Gate 4's reported 200/301 result. In the detailed evidence, distinguish origin HTTP responses, redirects, and proxy CONNECT acceptance; the latter can itself return 200. Attach any existing request log or route observation instead of changing the successful result. Explicitly show direct/fallback/SCION/unknown when that information is available. Chrome can reorder proxy choices after failures, and PAC-fetch failure can permit direct fallback depending on configuration. [Chrome fallback behavior](https://chromium.googlesource.com/chromium/src/+/HEAD/net/docs/proxy.md#evaluating-proxy-lists-proxy-fallback), [skip CONNECT implementation](https://github.com/netsec-ethz/scion-apps/blob/6c990ccb5b39fe0f7a23a3d8dcb4528439c3f5c5/skip/main.go)

10. **Make network status explain its evidence.** Show when paths were last checked, the source/target AS, the selected path's AS/interface sequence, and whether values are live, stale, or unavailable. `scion showpaths` probes by default; discovered paths can nevertheless fail to forward. Its reachability result is different from application success and from sustained multipath traffic. A control must distinguish requested state, applied state, and an error. Acceptance: visible values must follow real backend responses, not a timer, preset percentage, or optimistic button animation. [showpaths semantics](https://docs.scion.org/en/latest/command/scion/scion_showpaths.html)

11. **Check the installed versions before using examples.** The upstream latest-release URL currently resolves to SCION v0.15.1. Keep the active working installation unless a real compatibility issue requires a change. Record `scion version`, the scion-apps revision, GNS3 server version, and their own `--help`/API schema. GNS3 2.x and 3.x documentation coexist; do not hard-code an API version from the UI name. [SCION release](https://github.com/scionproto/scion/releases/tag/v0.15.1), [SCION commands](https://docs.scion.org/en/latest/command/scion/scion.html), [GNS3 3.1 documentation](https://docs.gns3.com/docs-3.1-en/web-ui/manage-computes)

12. **Reuse stock checks at the correct scope.** The documented source-development sequence is `make`, `./scion.sh topology -c topology/tiny.topo`, `./scion.sh run`, then `bin/end2end_integration`. Do not regenerate an active topology merely to review the UI. For that tiny topology, the documented path query is `bin/scion showpaths --sciond "$(./scion.sh sciond-addr 112)" 1-ff00:0:110`. Real endpoint examples are `scion ping <ISD-AS>,<IP> -c 5` and `scion traceroute <ISD-AS>,<IP>`, using values from the actual environment and the installed help. The default local Supervisor test stays on loopback; it does not by itself verify GNS3, cross-host WSL traffic, or Internet egress. In this development harness, SIG is supported by the Docker Compose mode. [Pinned local-run guide](https://docs.scion.org/en/v0.15.1/dev/run.html), [ping](https://docs.scion.org/en/latest/command/scion/scion_ping.html), [traceroute](https://docs.scion.org/en/latest/command/scion/scion_traceroute.html)
